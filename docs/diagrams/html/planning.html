Planning

The Staff Engineer studies specs, explores the codebase with parallel sub-agents, and drafts a structured plan.json before entering an adversarial 11-dimension evaluation loop. Each accepted plan carries a kind field that routes the phase shift to the correct implementation variant.

State 06a — Only when plan invalid
Validate
triggerauto on invalid plan.json
actionforgectl advance (re-validates)

Structural repair loop. Fix all errors, then re-advance — forgectl advance re-validates automatically.

Structural checks
  • JSON parse validity
  • Required fields present: context, refs, layers, items
  • context.domain & context.module non-empty
  • All ref paths resolve on disk
  • Item ID uniqueness across all items
  • Every item appears in exactly one layer
  • Layer ordering respects the dependency DAG
  • No dependency cycles
  • Test categories: functional, rejection, edge_case only
  • Notes files exist for all items[].refs entries
  • Spec files exist for all items[].specs entries

Verdict routing
EVALUATE ⟲ REFINE
PASS ≥ min_rounds → ACCEPT

State 09
Refine
actionforgectl advance

Address deficiencies surfaced by EVALUATE. Update plan.json and notes/*.md, then advance. Returns to SELF_REVIEW (when enabled) or directly to EVALUATE. If plan.json becomes invalid during refinement, re-enters VALIDATE first.

Loop path
REFINE → SELF_REVIEW* ⟲ EVALUATE
8
State 10 — Terminal
Accept
cmdforgectl advance [--message]
outplan.json finalized

Plan finalized. If enable_commits is set, a per-plan commit is created via forgectl advance --message. On advance, passes: "pending" and rounds: 0 are stamped onto every item in plan.json to initialize the implementing phase.

Queue routing after ACCEPT
plan_all: true + queue non-empty → PHASE_SHIFT planning → planning (next domain) → ORIENT
plan_all: true + queue empty → DONE → PHASE_SHIFT
plan_all: false → PHASE_SHIFT immediately after ACCEPT
Phase Shift — Routed by plan.json kind field
PHASE_SHIFT routed by kind: kind: "code" → implementing kind: "ui" → ui_implementing
kind Routing Field

Every plan.json carries a top-level kind field set during DRAFT. The field is stamped and immutable after ACCEPT. On PHASE_SHIFT, forgectl reads kind to select the correct implementing variant: kind: "code" routes to the standard Implementing phase (batch → eval → commit loop); kind: "ui" routes to UI Implementing, which inserts Playwright MCP QA and Playwright test-runner E2E gates after each code eval.

plan.json kind: "code" → implementing | plan.json kind: "ui" → ui_implementing
