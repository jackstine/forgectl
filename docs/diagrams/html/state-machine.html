State Machine

All 27 states across 5 phases — including both implementation variants (kind: code and kind: ui). Every state, branch, and loop drawn from the authoritative source. State is persisted atomically to .forgectl/state/forgectl-state.json.

01 Specifying
Per-spec loop (repeats until queue empty)
ORIENT→ SELECT→ DRAFT→ EVALUATE ⟲ REFINE→ ACCEPT
PASS ≥ min · or FAIL ≥ max → ACCEPT
FAIL < max · or PASS < min → REFINE → back to EVALUATE
Queue has more → loop back to ORIENT  ·  Queue empty → DONE
Reconciliation (after queue drains)
DONE→ RECONCILE→ RECONCILE_EVAL
PASS → RECONCILE_REVIEW → accept → COMPLETE
FAIL → RECONCILE_REVIEW → fail → loop back to RECONCILE
Phase exit
COMPLETE → PHASE_SHIFT specifying → generate_planning_queue
--message required at COMPLETE if enable_commits: true. PHASE_SHIFT can be bypassed with forgectl advance --from plan-queue.json.
States in this phase (10)
ORIENT SELECT DRAFT EVALUATE REFINE ACCEPT DONE RECONCILE RECONCILE_EVAL RECONCILE_REVIEW COMPLETE PHASE_SHIFT
PHASE_SHIFT specifying → generate_planning_queue  ·  or skip with advance --from plan-queue.json
02 Generate Planning Queue
Flow
ORIENT (generates plan-queue.json) → REFINE (architect review) → PHASE_SHIFT
ORIENT auto-generates plan-queue.json from completed specs.  REFINE: architect reorders and edits; forgectl validates on advance.  PHASE_SHIFT: consumes queue, transitions to planning ORIENT.  This entire phase can be skipped: forgectl advance --from <file> at specifying PHASE_SHIFT.
States in this phase (3)
ORIENT REFINE PHASE_SHIFT
PHASE_SHIFT generate_planning_queue → planning
03 Planning
Study → Draft → Evaluate
ORIENT→ STUDY_SPECS→ STUDY_CODE→ STUDY_PACKAGES→ REVIEW→ DRAFT
Validate → Self-review → Evaluate
DRAFT→ VALIDATE (if invalid) ⟲ SELF_REVIEW (optional*) → EVALUATE ⟲ REFINE → ACCEPT
PASS ≥ min · or FAIL ≥ max → ACCEPT
FAIL < max · or PASS < min → REFINE → back to EVALUATE or VALIDATE
* SELF_REVIEW entered only when planning.self_review: true
Phase exit — routed by plan_all flag
plan_all: false → PHASE_SHIFT planning → implementing (or ui_implementing)
plan_all: true, queue non-empty → PHASE_SHIFT planning → planning (domain boundary) → ORIENT next domain
plan_all: true, queue empty → DONE → PHASE_SHIFT planning → implementing
States in this phase (11)
ORIENT STUDY_SPECS STUDY_CODE STUDY_PACKAGES REVIEW DRAFT VALIDATE SELF_REVIEW EVALUATE REFINE ACCEPT DONE PHASE_SHIFT
PHASE_SHIFT routed by plan kind: kind: code → implementing kind: ui → ui_implementing
⑂ implementation forks on plan kind
04 Implementation
Phase 04a · kind: code
Implementing
Batch loop
ORIENT→ IMPLEMENT item 1..N→ EVALUATE ⟲ IMPLEMENT round 2+→ COMMIT→ DONE
PASS ≥ min · or FAIL ≥ max → COMMIT
FAIL < max → IMPLEMENT round 2+ → back to EVALUATE
More batches → loop back to ORIENT  ·  All done → DONE
DONE exit: plan_all: false + queue non-empty → PHASE_SHIFT to planning (next domain). plan_all: true + impl queue non-empty → PHASE_SHIFT implementation → implementation, re-routed by next plan's kind.
Phase 04b · kind: ui
UI Implementing
Loop 1 — Code eval (shared spine)
ORIENT→ IMPLEMENT 1..N→ EVALUATE ⟲ IMPLEMENT r2+
Loop 2 — QA (Playwright MCP)
QA_TEST ⟲ UI_REFINE
PASS ≥ min · or FAIL ≥ max → advance to E2E_AUTHOR
FAIL < max → UI_REFINE (iterate placement/controls) → back to QA_TEST
QA_TEST always writes qa/batch-N-steps.json before exiting
Bridge — Author e2e tests
E2E_AUTHOR (consumes qa/batch-N-steps.json)
Loop 3 — E2E (Playwright runner)
E2E_VERIFY ⟲ E2E_REMEDIATE
PASS ≥ min · or FAIL ≥ max → COMMIT
FAIL < max → E2E_REMEDIATE (fix tests or UI) → back to E2E_VERIFY
Commit & exit
COMMIT→ DONE
COMMIT status: passed if all 3 loops passed; force-accepted if any loop hit max_rounds. Three independent round budgets: eval / qa / e2e. DONE exit uses same routing as implementing.
Shared states (both variants)
ORIENT IMPLEMENT EVALUATE COMMIT DONE PHASE_SHIFT
UI-only states (kind: ui)
QA_TEST UI_REFINE E2E_AUTHOR E2E_VERIFY E2E_REMEDIATE
PHASE_SHIFT → planning (next domain) if plans remain  ·  domain boundaries re-route by kind
