Reverse Engineering

The inverse of the specifying phase — specs are extracted FROM existing code, not authored from planning documents. The Go CLI drives the entire workflow: it emits action output telling the orchestrating agent what to do at each state, but invokes no subprocess and writes no specs itself. The agent reads code; forgectl sequences the states.

Role Systems Architect (inverse) Input reverse-engineering-init.json { concept, domains[] } Output <domain>/specs/*.md derived from code State file .forgectl/state/forgectl-state.json
Init Contract
Init Input

The phase is bootstrapped from reverse-engineering-init.json. The concept defines the work scope (what codebase area to reverse-engineer); domains[] is an ordered list driving both the analysis loop and the reconcile loop. The queue file path is fixed by convention — no --file flag is accepted in QUEUE.

concept · domains[] → ORIENT → domain index = 1

For each domain (in init order), the agent surveys existing specs, identifies code behavior not yet covered, decomposes it into spec topics, then writes queue entries. A single shared queue file accumulates entries across all domains at .forgectl/state/reverse-engineering-queue.json. After all domains are queued the loop exits and execution begins.

States — per domain
SURVEY → GAP_ANALYSIS → DECOMPOSE → QUEUE ⟲ SURVEY next domain
SURVEY read existing specs in <domain>/specs/
GAP_ANALYSIS find code behavior not covered by a spec; assign topic of concern
DECOMPOSE synthesize specs to create/update; define topic, file, roots, depends_on
QUEUE write/append entries to the single queue file at the fixed path
Loop transition
QUEUE → SURVEY domain += 1 until all domains queued → EXECUTE_REVERSE_ENGINEER

B
Loop B — Across all queued items, in queue order
Execution
Role: Systems Architect (inverse)
inreverse-engineering-queue.json
incode_search_roots (per item)
out<domain>/specs/*.md

Items are processed in queue order. Each item is a single-pass spec write — no draft, no eval, no refine cycle per spec. The agent reads code under code_search_roots and writes the final spec directly. A POST_REVERSE_ENGINEER checkpoint clears context before the next item. Adversarial evaluation happens only at reconcile, not here.

States — per item
EXECUTE_REVERSE_ENGINEER item N → POST_REVERSE_ENGINEER item N ⟲ EXECUTE_REVERSE_ENGINEER item N+1
EXECUTE write the final spec for one item from code under its code_search_roots — single pass
POST STOP / clear-context checkpoint; agent re-initializes before next item
Edge cases
ERROR empty queue on loop entry → "Queue contains zero entries."
SKIP agent writes no file for an item → item skipped silently; no failure state entered
mkdir specs/ directory is created (if absent) before each item's action output
Last item transition
POST_REVERSE_ENGINEER last item → RECONCILE domain 1, round 1
Per-Domain Reconciliation Loop
C
Loop C — For each domain, same order as analysis
Reconciliation
Role: Systems Architect (inverse)
in<domain>/specs/*.md
evalreconcile-eval prompt
outstaged git changes

Specs are wired together domain-by-domain. RECONCILE fills in Depends On from depends_on fields and validates symmetric Integration Points, then stages git changes. RECONCILE_EVAL runs adversarial review; PASS advances, FAIL loops back with round += 1. An optional colleague review gate sits between eval and the domain-transition state. Round resets to 1 on each new domain. When all domains are reconciled the phase terminates at DONE.

Per-domain reconcile states
RECONCILE → RECONCILE_EVAL ⟲ RECONCILE round += 1
Eval verdict fork
PASS ≥ min_rounds or FAIL ≥ max_rounds → advance out of the retry loop
FAIL < max_rounds or PASS < min_rounds → RECONCILE (round N)
Colleague review gate (optional)
RECONCILE_EVAL passed → colleague_review?
enabled → COLLEAGUE_REVIEW → RECONCILE_ADVANCE
disabled (default) → RECONCILE_ADVANCE
Domain transition
RECONCILE_ADVANCE ⟲ RECONCILE next domain, round = 1 until all domains reconciled → DONE
State-Gated Commands
CLI Commands

The Go CLI enforces which commands are valid in each state. These three commands have hard state guards — invoking them outside their allowed state returns an error.

Command Active State Purpose
forgectl add-domain QUEUE only Append a domain to the init list; does NOT re-run analysis
forgectl eval RECONCILE_EVAL only Output embedded reconcile-eval prompt for the eval sub-agents
forgectl advance QUEUE: no --file Queue path is fixed; --file is rejected in QUEUE state
State File Tracking
Tracked Fields — .forgectl/state/forgectl-state.json

The state file persists all runtime indexes and flags that drive the two nested loops and the reconcile round counter.

current_state Active state machine state
domain_index Drives both analysis loop and reconcile loop
domain_count Total number of domains from init
execute_item_index Drives EXECUTE → POST loop (per-item)
reconcile_round Current reconcile round; resets to 1 per domain
queue_file_path Set on first QUEUE advance; fixed convention
queue_file_hash Content hash for change detection on subsequent QUEUE advances
colleague_review Enabled flag (disabled by default)
