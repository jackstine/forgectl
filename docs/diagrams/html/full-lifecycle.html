Planning readiness gate — cold-start precondition
Every domain in the plan queue about to drive planning must have an empty workspace at <domain-path>/<workspace_dir>/ (default .forge_workspace). Absent, empty, or holding only empty subdirectories counts as clean; any regular file at any depth — a leftover plan.json, an eval report, even a lone .gitkeep — counts as dirty, as does a directory that cannot be traversed.

Blocked → the entry is refused, the dirty domains and their paths print with the workspace close-out remediation, exit 1. Nothing is mutated: init writes no state file, a phase shift performs no transition.

Gated (the three cold-start entries): init --phase planning --from <queue> · the generate_planning_queue → planning shift · the specifying → generate_planning_queue --from skip.
Not gated (intra-session domain boundaries): planning → planning · implementing/ui_implementing → planning. Cold start already inspected every domain in this cycle's queue; re-gating would false-block the multi-domain continuation, whose earlier domains now legitimately hold a full workspace.

Query it at any time, mutating nothing: forgectl preflight [--from <plan-queue.json>]. The gate is stateless — it records no marker and stores nothing in the state file.

Phase 04a — Forge · kind: code
Implementing
Role: Senior Software Engineer
inplan.json +passes
outproduction code
outeval reports

The default code path. Implements each batch item, evaluates, and commits. FAIL re-enters implement at round 2+ — or re-enters EVALUATE directly under eval_mode: direct; more batches loop back until the queue drains.

Batch loop
ORIENT→ IMPLEMENT 1..n · auto-commits every round→ EVALUATE ⟲ IMPLEMENT r2+→ COMMIT enable_commits: false only→ DONE
terminal verdict branches on enable_commits — true: the batch auto-commits inline on that same advance and lands straight on ORIENT / DONE, COMMIT never appears. false: COMMIT, a bookkeeping state with no git operation.
non-terminal verdict branches on eval_mode — report / conversational: IMPLEMENT round 2+. direct: EVALUATE self-loop, since the evaluator already made the corrections; IMPLEMENT runs once per batch and the self-loop carries the round increment.

Phase 04b — Forge + Quench · kind: ui
UI Implementing
Role: Senior Software Engineer (UI)
inplan.json +passes
outUI code + e2e
outQA + eval reports

Reuses the implementing spine, then inserts two verification loops between code eval and commit — three sequential gates per batch. An item passes only if all three loops pass within budget.

Three gates per batch
ORIENT→ IMPLEMENT→ CODE EVAL→ QA ⟲ UI_REFINE→ E2E ⟲ E2E_REMEDIATE→ COMMIT enable_commits: false only→ DONE
QA Playwright MCP — visual + interaction (QA_TEST / UI_REFINE)
E2E Playwright test runner — authored specs (E2E_VERIFY / E2E_REMEDIATE)
batch terminal same branch as implementing — enable_commits: true auto-commits the batch inline on the terminal E2E_VERIFY advance and skips COMMIT; false enters COMMIT with no git operation. Item status is decided at that boundary.
