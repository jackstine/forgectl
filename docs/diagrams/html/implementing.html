Implementing

The default code path — entered when a plan carries kind: "code". Batches of unblocked items are implemented, evaluated by an AI sub-agent, and committed in bounded rounds until the queue drains or the max is forced.

Role Senior Software Engineer Input plan.json (passes / rounds) Output production code + IMPLEMENTATION_LOG.md Eval AI sub-agent vs spec tests
Initialization
⚙
Entry Point
Init
Via PHASE_SHIFT from planning — or manual
cmdforgectl init
flag--phase implementing
flag--guided (optional)

Reads plan.json from the domain workspace and stamps every item with passes: "pending" and rounds: 0. Batch size and round limits come from .forgectl/config (batch, eval.max_rounds). Pass --guided to insert user checkpoints at every ORIENT.

Command
forgectl init --from <domain>/.forge_workspace/implementation_plan/plan.json --phase implementing

Item Loop · Round 1
Implement
actionforgectl advance
flag--message "<what I did>"

One item at a time within the batch. forgectl displays the item card; the engineer reads spec contracts, consults notes, verifies the feature isn't already implemented, writes complete code with no stubs, runs tests, and fixes failures. --message is required on round 1 when enable_commits: true — this fires the auto-commit. Item advances from pending → done.

Verdict routing
EVALUATE →
PASS ≥ min_rounds → COMMIT  ·  items: passed
PASS < min_rounds ⟲ IMPLEMENT r2+  (still must hit min)
FAIL < max_rounds ⟲ IMPLEMENT r2+  (fix deficiencies)
FAIL ≥ max_rounds → COMMIT  ·  items: failed (force-accept)
Re-implement (round 2+)
IMPLEMENT r2+ → EVALUATE ⟲
eval_mode: report → study eval file  ·  direct → review diff  ·  conversational → relay verbally
No --message flag  ·  No auto-commit on round 2+
Advance commands
forgectl advance --eval-report <path> --verdict PASS|FAIL  (eval_mode: report) forgectl advance --verdict PASS|FAIL  (eval_mode: direct | conversational)

Hard pause at the batch boundary. Commits include both passed and force-accepted failed items. When enable_commits: false, forgectl advance proceeds without committing.

statepassed or failed
outIMPLEMENTATION_LOG.md

All layers complete, all items marked passed or failed. A summary is displayed for this domain. Transition depends on the remaining plan queue and the plan_all_before_implementing config flag.

Transition routing
plan_all_before_implementing: false (interleaved)
planning queue non-empty → PHASE_SHIFT (implementing → planning, next domain)
planning queue empty → session complete
plan_all_before_implementing: true (all-planning-first)
implementation plan queue non-empty → PHASE_SHIFT (domain boundary; next plan routes by kind)
implementation plan queue empty → session complete
PHASE_SHIFT → planning (next domain) if plans remain · domain boundaries re-route by kind
Batch Selection Algorithm
B Unblocked Items & Layer Progression

An item is unblocked when all items in prior layers have terminal passes (passed | failed) and all items in its depends_on[] have terminal passes. The batch takes up to implementing.batch unblocked items, selected in layer items[] order.

Layer 0 — Foundation

item.b
Layer 1 — Core
item.c

Layer 2 — Integration
item.e
item.f
Layer dependency arrow
Layer 0 Foundation → Layer 1 Core → Layer 2 Integration

Note: failed items are terminal — they do not block dependents.

Item Progress Tracking
T plan.json Item State Machine

Fields passes and rounds are stamped onto each item by PHASE_SHIFT from planning. rounds increments on each evaluation cycle.

From state Condition To state
pending advance in IMPLEMENT done
done PASS + rounds ≥ eval.min_rounds passed
done FAIL + rounds ≥ eval.max_rounds failed
done FAIL + rounds < eval.max_rounds done (stays — re-implement)
done PASS + rounds < eval.min_rounds done (stays — refine more)
Kind Routing
This is the kind: code variant

This page documents the default implementing path, entered when a plan's kind field is "code". Plans with kind: "ui" are routed at PHASE_SHIFT into ui_implementing — the same spine extended with two additional verification gates (Playwright MCP QA + Playwright e2e test runner) before each commit.
