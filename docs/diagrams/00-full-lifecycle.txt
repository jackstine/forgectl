================================================================================
                     FORGECTL — FULL DEVELOPMENT LIFECYCLE
================================================================================

  A spec-driven development harness that compiles planning documents into
  production code through sequential phases, each governed by a state machine
  with iterative AI-powered evaluation loops. The implementation phase has two
  variants — implementing (code) and ui_implementing (code + UI verification) —
  selected per plan by its "kind" field.

                     │
                     │  ╔══════════════════════════════════════════════════╗
                     │  ║  PLANNING READINESS GATE — cold-start entry only ║
                     │  ║                                                  ║
                     │  ║  Every domain in the plan queue about to drive   ║
                     │  ║  planning must have an EMPTY workspace at        ║
                     │  ║  <domain-path>/<workspace_dir>/ (default         ║
                     │  ║  .forge_workspace). Absent, empty, or holding    ║
                     │  ║  only empty subdirectories = clean; any regular  ║
                     │  ║  file at any depth — a leftover plan.json, an    ║
                     │  ║  eval report, even a lone .gitkeep — = dirty.    ║
                     │  ║                                                  ║
                     │  ║  BLOCKED → the entry is refused, the dirty       ║
                     │  ║  domains and their paths are printed with the    ║
                     │  ║  workspace close-out remediation, exit 1.        ║
                     │  ║  Nothing is mutated: init writes no state file,  ║
                     │  ║  a phase shift performs no transition.           ║
                     │  ║                                                  ║
                     │  ║  Gated (the three cold-start entries):           ║
                     │  ║    · init --phase planning --from <queue>        ║
                     │  ║    · generate_planning_queue → planning shift    ║
                     │  ║    · specifying → gen_plan_queue --from skip     ║
                     │  ║  NOT gated (intra-session domain boundaries):    ║
                     │  ║    · planning → planning                         ║
                     │  ║    · implementing / ui_implementing → planning   ║
                     │  ║  Those were already covered by the cold-start    ║
                     │  ║  check; re-gating would false-block the          ║
                     │  ║  multi-domain continuation, whose earlier        ║
                     │  ║  domains now legitimately hold a full workspace. ║
                     │  ║                                                  ║
                     │  ║  Query it at any time, mutating nothing:         ║
                     │  ║    forgectl preflight [--from <plan-queue.json>] ║
                     │  ╚══════════════════════════════════════════════════╝

                     │  PHASE_SHIFT  (context refresh)

  │                                                                         │
  │   ORIENT ─► IMPLEMENT(1..n) ─► [ CODE EVAL ] ─► [ QA ] ─► [ E2E ] ─►    │

  │                                               MCP)          test runner)│

  │   Item passed only if all three loops PASS within budget; else failed.  │

  ═══════════════════════════════════════════════════════════════════════════
  KEY
  ═══════════════════════════════════════════════════════════════════════════

  ──►  State transition (forgectl advance)
  │    Sequential flow
  ◄──  Loop back / retry

  PHASE_SHIFT    Hard stop between phases and at domain boundaries;
                 engineer refreshes context before proceeding
  EVALUATE       AI sub-agent reviews work against evaluation dimensions
  REFINE         Fix deficiencies found in evaluation
  COMMIT         Bookkeeping pause reached only when enable_commits: false;
                 no git operation occurs there. With commits enabled the
                 batch-terminal commit runs inline on the terminal EVALUATE
                 (implementing) or E2E_VERIFY (ui_implementing) advance and
                 COMMIT never appears
  GUIDED         Optional pause for human discussion (--guided flag)
  READINESS GATE Cold-start precondition on entering planning: every incoming
                 domain's workspace must be empty. Query with
                 forgectl preflight; remediate with workspace close-out

  Round Enforcement (from .forgectl/config [phase].eval):
    eval.min_rounds   PASS below minimum forces another REFINE cycle
    eval.max_rounds   FAIL at maximum forces acceptance (prevents infinite loops)
    eval_mode         Where a non-terminal verdict lands. report and
                      conversational hand work back (REFINE, or IMPLEMENT
                      round 2+); direct loops the implementation phases'
                      EVALUATE back onto itself — the evaluator already made
                      the corrections, so IMPLEMENT runs once per batch and
                      the self-loop carries the round increment

  Mode Control (general config):
    plan_all_before_implementing: false (default)
      Interleaved: plan domain → implement domain → plan domain → ...
    plan_all_before_implementing: true
      All planning first, then all implementing (PHASE_SHIFT at each domain boundary)

  Implementation routing (per plan):
    kind: code (default) → implementing      (code-only batches)
    kind: ui             → ui_implementing    (code batches + QA + e2e loops)
    The planning → implementation PHASE_SHIFT reads kind to pick the variant;
    ui_implementing additionally requires ui_implementing.app.* and .e2e.* config.

  Config & State:
    .forgectl/config                  TOML config file (phase-scoped)
    .forgectl/state/forgectl-state.json State file (JSON)
