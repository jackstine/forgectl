================================================================================
                    FORGECTL CLI — Command Reference Map
================================================================================

  Binary: forgectl (Go, Cobra framework)
  State:  .forgectl/state/forgectl-state.json (JSON-backed state machine)


  forgectl
  │
  ├── init ─────────────── Initialize a new session
  │   │
  │   │  Required flags:
  │   │    --from <path>  Input file (spec-queue, plan-queue, or plan.json)
  │   │    --phase <str>  Phase: specifying | planning | implementing |
  │   │                          ui_implementing
  │   │
  │   │  Optional flags:
  │   │    --guided       Enable guided mode (user checkpoints)
  │   │    --no-guided    Disable guided mode
  │   │
  │   │  Bootstrap:
  │   │    Creates .forgectl/ and a default .forgectl/config (from the
  │   │    embedded template) when missing. Reuses an ancestor .forgectl/
  │   │    if found; never overwrites an existing config.
  │   │
  │   │  Configuration:
  │   │    All config (batch, eval.min_rounds, eval.max_rounds) read from
  │   │    .forgectl/config (TOML). Phase-scoped:
  │   │      [specifying]
  │   │        batch = 1
  │   │        [specifying.eval]
  │   │          min_rounds = 1
  │   │          max_rounds = 3
  │   │      [general]
  │   │        enable_commits = false
  │   │
  │   │  Input by phase:
  │   │    specifying      ──►  spec-queue.json
  │   │    planning        ──►  plan-queue.json
  │   │    implementing    ──►  plan.json
  │   │    ui_implementing ──►  plan.json (+ requires ui_implementing.app.*
  │   │                          and ui_implementing.e2e.* config, non-empty)
  │   │
  │   │  State file location: .forgectl/state/forgectl-state.json
  │   │
  │   └─── Output: state initialized
  │
  │
  ├── advance ──────────── Transition to next state
  │   │
  │   │  Context-dependent flags:
  │   │
  │   │  ┌─────────────────┬─────────────────────────────────────────────┐
  │   │  │ Current State    │ Valid Flags                                 │
  │   │  ├─────────────────┼─────────────────────────────────────────────┤
  │   │  │ ORIENT           │ (none required)                            │
  │   │  │ SELECT           │ (none required)                            │
  │   │  │ DRAFT            │ --file <path>  (override output, spec only)│
  │   │  │ EVALUATE         │ --verdict PASS|FAIL                        │
  │   │  │                  │ --eval-report <path>  (if report mode)     │
  │   │  │ REFINE           │ (none required)                            │
  │   │  │ ACCEPT           │ --message (planning, if enable_commits)    │
  │   │  │ IMPLEMENT        │ --message (first round, if enable_commits) │
  │   │  │ COMMIT           │ --message (if enable_commits)              │
  │   │  │ QA_TEST          │ --verdict PASS|FAIL  (ui_implementing)     │
  │   │  │   (UI)           │ --eval-report <path>  (if qa report mode)  │
  │   │  │ UI_REFINE  (UI)  │ (none required)                            │
  │   │  │ E2E_AUTHOR (UI)  │ (none required)                            │
  │   │  │ E2E_VERIFY       │ --verdict PASS|FAIL  (ui_implementing)     │
  │   │  │   (UI)           │ --eval-report <path>  (if e2e report mode) │
  │   │  │ E2E_REMEDIATE(UI)│ (none required)                            │
  │   │  │ RECONCILE        │ (none required)                            │
  │   │  │ RECONCILE_EVAL   │ --verdict PASS|FAIL  --eval-report <path>  │
  │   │  │ RECONCILE_REVIEW │ (none required)                            │
  │   │  │ COMPLETE         │ --message (specifying, if enable_commits)  │
  │   │  │ PHASE_SHIFT      │ --from <path>  (specifying or gen_plan_q)  │
  │   │  │ SELF_REVIEW      │ (none required)                            │
  │   │  │ STUDY_*          │ (none required)                            │
  │   │  │ REVIEW           │ (none required)                            │
  │   │  │ VALIDATE         │ (none required)                            │
  │   │  └─────────────────┴─────────────────────────────────────────────┘
  │   │
  │   │  Mode toggles (any state):
  │   │    --guided / --no-guided
  │   │
  │   └─── Output: Updated state + formatted status
  │
  │
  ├── status ──────────── Print current state with action guidance
  │   │
  │   │  No additional flags (inherits --dir from root)
  │   │
  │   └─── Output: Human-readable status, next action, overview
  │
  │
  ├── eval ────────────── Output evaluation context for sub-agent
  │   │
  │   │  Valid in EVALUATE; plus QA_TEST and E2E_VERIFY (ui_implementing)
  │   │  No additional flags
  │   │
  │   └─── Output: Full context needed by AI evaluator
  │                (items, specs, tests, evaluator prompt)
  │                ui_implementing — QA_TEST embeds ui-qa-eval.md + app url +
  │                step-list path; E2E_VERIFY embeds ui-e2e-eval.md + test cmd
  │
  │
  ├── handoff ─────────── Register sub-agent artifacts back to the scaffold
  │   │                   (ui_implementing only — the inverse of eval)
  │   │
  │   │  Arguments:
  │   │    <file> [<file>…]  One or more generated files to register
  │   │                      (QA report, QA step list, e2e report)
  │   │
  │   │  Valid in: EVALUATE, QA_TEST, E2E_VERIFY (same states as eval)
  │   │  Verifies each file exists; surfaces them on a "Review:" line so the
  │   │  engineer reviews them before recording a verdict. Carries NO verdict;
  │   │  coexists with --eval-report (a divergent path warns, does not block).
  │   │
  │   └─── Output: "Registered N artifact(s) for review."
  │
  │
  ├── add-queue-item ───── Append a spec to the specifying queue
  │   │
  │   │  Required flags:
  │   │    --name <str>    Spec name (must be unique)
  │   │    --topic <str>   Topic of concern
  │   │    --file <path>   Path to spec file (must exist, must match
  │   │                    <domain>/specs/<name>.md convention)
  │   │
  │   │  Optional flags:
  │   │    --domain <str>  Domain name (required when no match found)
  │   │
  │   │  Domain resolved from: configured domains → session domains
  │   │  Valid in: DRAFT, CROSS_REFERENCE_REVIEW, DONE, RECONCILE_REVIEW
  │   │
  │   └─── Output: "Added {name} to specifying queue for domain {domain}."
  │
  │
  ├── set-roots ────────── Set code search roots for a domain
  │   │
  │   │  Required flags:
  │   │    --domain <str>  Domain name
  │   │    --roots <str>   Comma-separated list of root paths
  │   │
  │   │  Writes to specifying.domains[<domain>].code_search_roots
  │   │
  │   └─── Output: "Set code search roots for {domain}."
  │
  │
  ├── set-commit-hashes ── Set commit hashes for a domain
  │   │
  │   │  Flags:
  │   │    --domain <str>  Domain name (required at DONE, inferred elsewhere)
  │   │    (positional)    One or more commit hashes
  │   │
  │   │  Overwrites commit_hashes on every completed spec in the domain.
  │   │  Valid in: CROSS_REFERENCE_REVIEW, DONE
  │   │
  │   └─── Output: "Set commit hashes for domain {domain}: [{hashes}]"
  │
  │
  ├── generate-workflow ── Compile a plan.json into a Claude Code workflow script
  │   │
  │   │  Arguments:
  │   │    <plan.json>     Path to a produced plan; validated before emission
  │   │
  │   │  Optional flags:
  │   │    -v, --verbose   Log resolved config + per-batch item ids (DEBUG)
  │   │
  │   │  Reads the active .forgectl/config; bakes implementing.{batch,implement,
  │   │  eval} + general.enable_commits into the emitted adversarial-gauntlet loop.
  │   │  Writes ONE self-contained script to
  │   │  .claude/workflows/<domain>-<module>-impl.js (collision → prefixed fresh
  │   │  name, never overwrites). Plan and config are read-only.
  │   │
  │   └─── Output: "wrote workflow <path> (slash command: /<domain>-<module>-impl)"
  │
  │
  └── --version ───────── Display version (v0.0.1)

  ┌─────────────────────────┐         ┌─────────────────────────┐
  │    ENGINEER              │         │    SUB-AGENT (AI)        │
  │    (Primary Agent)       │         │    (Evaluator)           │
  │                          │         │                          │
  │  Uses:                   │         │  Uses:                   │
  │    forgectl init         │         │    forgectl eval         │
  │    forgectl advance      │         │    forgectl handoff      │
  │    forgectl status       │         │      (ui_implementing)   │
  │    forgectl add-queue-   │         │                          │
  │             item         │         │  Reads:                  │
  │    forgectl set-roots    │         │    - Spec files          │
  │                          │         │    - Implementation      │
  │  Writes:                 │         │    - Notes/refs          │
  │    - Specs               │         │    - Evaluator prompt    │
  │    - Plans               │         │                          │
  │    - Code                │         │  Writes:                 │
  │    - Notes               │         │    - Eval reports        │
  │                          │         │    - QA reports/steps    │
  │                          │         │    - e2e tests/reports   │
  └──────────┬───────────────┘         └──────────┬───────────────┘
             │                                     │
             │    forgectl advance                  │   forgectl eval (context in)
             │    --verdict --eval-report           │   forgectl handoff (files back)
             │                                     │
             └──────────────┬──────────────────────┘
                            │
                            ▼
                     ┌──────────────────────────────┐
                     │  .forgectl/state/            │
                     │  forgectl-state.json (state) │
